# 离线安全框验收 crop v1

合成组在任意子帧叠加画面，而不是只渲染采样表上的帧；剪辑师另给一个随时间收放的矩形安全框。`rig-pose-crop` 提供离线验收：动画方用 `check` 对整个闭合验收区间做精确判定并产出带纯数据凭证的 JSON 报告；合成方用 `verify` 只凭原请求与报告独立核验凭证——不相信报告写下的结论，也不重跑找越界的检查任务。运行仅标准库，无新增运行时依赖。

```sh
rig-pose-crop check --request FILE --output FILE
rig-pose-crop verify --request FILE --report FILE
```

## 请求

请求文件是最多 8,000,000 字节的 UTF-8 严格 JSON（拒绝重复键、非有限数），顶层仅含两个字段：

- `source`：合法的现有 `rig-pose` 源对象，按 [采样契约](contract.md) 完整校验（含 `sample_ticks` 及其工作上限）。采样表不决定验收范围。
- `viewport`：2 到 21 条安全框键，每条仅含 `tick`、`min`、`max`。`tick` 与原轨道键同域（0..10⁶ 整数，严格递增）；`min`、`max` 各为两个旧格式十进制字符串，逐轴要求 min 严格小于 max。

工具专属上限（不收紧旧入口）：顶点最多 32 个；任一挂有顶点影响的关节到其根含两端最多 6 层；验收区间内安全框键与这些链上轨道键的合并不同切点（含首末）最多 21 个。违反任一限制是输入错误（退出 2）。

## 时间口径与判定

首末安全框键定义闭合验收区间 [T0, T1]。两键之间四条边（左 min.x、右 max.x、下 min.y、上 max.y）各自作精确线性插值。旧轨道端值保持、局部矩阵替换、父子乘积、加权蒙皮同样适用于区间内任意实数时刻。允许奇异姿态；它不是越界。

切点 = 安全框键 tick 与链上轨道键 tick 落在 [T0, T1] 内的并集（含首末）。相邻切点之间每个矩阵系数是 t 的一次多项式，世界矩阵系数次数 ≤ 6，顶点坐标与四条边也都是有理系数多项式。于是每条约束归结为：某段 [a, b] 上有理多项式 p(t) ≥ 0 恒成立——

- `(x, min)`：p = x(t) − 左边(t)；`(x, max)`：p = 右边(t) − x(t)
- `(y, min)`：p = y(t) − 下边(t)；`(y, max)`：p = 上边(t) − y(t)

只要存在一个时刻、一个顶点严格越过当时的任一条边（p(t) < 0），结论就是 `unsafe`；恰好贴边是 `safe`，前提是其余位置也未越界。线段由两端顶点确定，检查所有顶点（包括未接边的顶点）即可覆盖线稿，不扩大到控制骨骼或线宽。判定不使用浮点容差、不只看采样/关键帧、不做抽样。两个结论都是正常结果。

## 报告

`check` 把报告原子新建到 `--output`（写临时文件 + fsync + 硬链接生效），不覆盖已有文件或符号链接；成功退出 0，结论以新报告为准。报告是 JSON 对象，恰好含：

- `schema_version`：1
- `tool`：`"rig-pose-crop"`
- `status`：`"safe"` 或 `"unsafe"`
- `request_sha256`：实际解析的请求原始字节的 SHA-256 小写十六进制
- `credential`：有版本的纯数据凭证（`version`: 1，`kind` 与 `status` 一致）

### unsafe 见证

`kind` 为 `"unsafe"` 时凭证仅含 `witness`：

```json
{"vertex": "v", "axis": "x", "side": "min",
 "tick": "3/4", "coordinate": "1/64", "boundary": "1/4"}
```

顶点 ID、轴（`x`/`y`）、哪一侧（`min`/`max`）、区间内的有理数时刻、该时刻的顶点坐标和边界值。三个数用约分后的整数/分数字符串（见下）。不要求最早的时刻。

核验规则：时刻落在 [T0, T1]；从请求重算该时刻的顶点坐标与对应边值并与凭证逐项相等；`min` 侧要求坐标严格小于边界，`max` 侧要求坐标严格大于边界。

### safe 精确证明

`kind` 为 `"safe"` 时凭证含 `segments`：与请求切点一一对应的分段列表，每段 `{"range": ["a","b"], "constraints": [...]}`。`constraints` 恰好覆盖该段全部 顶点×4 条边 的约束（缺一项、多一项、重复都不被接受），每项 `{"vertex","axis","side","proof"}`。

`proof` 两种形状之一：

- `{"zero": true}`：该约束多项式恒等于 0（整段恒等贴边）。核验：重建的 p 所有系数为 0。
- `{"zero": false, "odd": [...], "square": [...], "sturm": [...], "quotients": [...]}`：非负性证明。

多项式编码：系数数组，低次在前，不得有尾零；零多项式是空数组。有理数编码：约分后的整数字符串（`"3"`、`"-2"`）或分数字符串（`"3/4"`、`"-1/2"`，分母 ≥ 2 且与分子互素）。

证明声明 p = odd·square²（odd 无重根），并给出 odd 的 Sturm 链。核验步骤（全部精确有理数运算）：

1. 从请求重建该约束的多项式 p（次数 ≤ 6），确认 p = odd·square²（逐系数相等）。
2. 确认 `sturm` = [S₀,…,S_k]：S₀ = odd；k ≥ 1 时 S₁ = odd′；`quotients` 长度 = k，且对每个 i 满足 S_{i−1} = q_i·S_i − S_{i+1}（S_{k+1} 为零多项式）；S_k 是非零常数。这些代数关系蕴含 odd 无重根、该链是 odd 的合法 Sturm 序列。
3. 在 a、b 两处对链求值并数符号变化（跳过零值）：Sturm 定理给出 (a,b) 内变号根数 = V(a) − V(b) −（b 是根则减 1），必须为 0。
4. 端点条件：odd(a) ≥ 0、odd(b) ≥ 0；odd(a) = 0 时要求 odd′(a) > 0；odd(b) = 0 时要求 odd′(b) < 0。

可靠性：p = odd·square² 且 square² ≥ 0，故 p < 0 ⟺ odd < 0（square 为零处 p = 0 不算越界）。odd 无重根，(a,b) 内无根说明内部不变号；端点非负加导数条件排除从端点向区间内变负。于是 p 在 [a, b] 恒非负。覆盖完整性由分段列表与约束集合的精确比对保证；证明与当前请求的绑定由 request_sha256 加全部重建比对共同保证（仅改摘要搬不动旧凭证）。

verify 只做上述代数关系核验与求值：不分解因式、不构造 Sturm 链、不隔离根、不搜寻违例。

## verify 行为

`verify` 把报告视为不可信输入：从请求重新确定实际运动、安全框及全部要核验的顶点与边界范围，再核对报告给出的证明或见证。验证成功退出 0，stdout 输出 `{"status":"safe"}` 或 `{"status":"unsafe"}`（后者表示越界属实，不表示镜头可投产）。请求、报告或 I/O 错误（含缺一项覆盖、伪造坐标、证明与当前请求不符、缺失/未知版本/损坏的凭证）退出 2，stderr 给可读诊断，不输出成功对象，也不留下新报告。报告文件最多 1,000,000,000 字节。

## 验收示例

`examples/acceptance.py` 离线演示完整验收链：四级缩放链顶点在中间恰贴左边 → check 出 safe 凭证、verify 接受；左边抬高 0.25 → check 改报 unsafe 并给出可核验见证、verify 确认越界属实；篡改见证时刻、搬运旧凭证、删除一项覆盖 → verify 一律退出 2 拒绝。运行：

```sh
python3 examples/acceptance.py
```
