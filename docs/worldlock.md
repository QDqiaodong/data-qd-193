# 离线挂点世界锁定 worldlock v1

动画师要替换一条上游关节的控制轨，但某些道具已经摆好位置：挂点及其下方的线稿在交付动画里必须原地不动。`rig-pose-worldlock --request FILE --output FILE` 把这次控制轨替换与挂点补偿**编译成一份普通的 `rig-pose` 源文件**——后续同事仍用现有工具打开、采样和编辑交付件，交付的不是逐帧坐标表。运行仅标准库，无新增运行时依赖。

锁的目标是编辑**前**该关节的完整世界仿射矩阵（不是局部矩阵、不是原采样帧、不是某个探针点）。交付源按旧关键帧插值和端值保持规则求值，在整个闭区间 [0, 10⁶] 的**每个实数 tick** 都必须得到相同的锁定世界矩阵。锁下未编辑关节继续用原本地变换，其世界姿态因此也保持；锁定子树之外的部分不要求保持不变。全程精确有理数运算，不用浮点容差或量化误差满足锁定。

## 请求

请求文件是最多 8,000,000 字节的 UTF-8 严格 JSON（拒绝重复键、非有限数），顶层仅含三个字段：

- `source`：完整合法的原版源对象，按 [采样契约](contract.md) 完整校验（含原采样表）。
- `edit`：一条原格式轨道（`joint_id`、`keys`），替换该关节的原轨道；该关节没有原轨道则新增。关节的默认 local 不变。
- `locks`：1 到 8 条锁定记录，每条仅含 `joint_id`、`key_ticks`、`allow_detach`。

锁定约束（违反是输入错误，退出 2）：

- 锁定关节必须是被编辑关节的**严格后代**；锁定关节不得重复；任意两个锁定关节不能互为祖先和后代。
- `key_ticks` 是允许写入补偿轨的完整键时刻表：1 到 32 个按原 tick 规则（0..10⁶ 整数）严格递增的时刻；补偿轨只用这些键，不另插键。
- `allow_detach` 是布尔值。
- 工具专属上限（不收紧其他命令）：每条锁定关节到根（含两端）最多 6 层；对每条这样的链，源轨道键、替换轨道键、该锁的补偿键以及 0、10⁶ 合并去重后最多 80 个时刻。

## 交付形态

每个锁有一种或两种合法的交付形态：

- **保留挂接（`kept`）**：锁定关节的 parent 不变，写一条补偿轨替换其原轨道。
- **脱挂（`detached`）**：仅当 `allow_detach` 为 true 时获准。把锁定关节的 parent 设为 null，再写一条补偿轨；后代的挂接不变。

无论选哪种，都只替换该锁定关节的轨道，且必须使用给定的 `key_ticks`，全部键矩阵系数必须能用旧的有界十进制格式（整数最多 9 位、小数最多 6 位）**精确**表达。不得改其他关节的 parent 或 local，不得借移动蒙皮绑点、改权重、拆骨架或改采样表来达到视觉上的近似；原边和顶点资料不变。同时绑定锁内与锁外关节的混合顶点，仍由原采样器按修订后各关节的实际姿态求和——锁内贡献原地不动，锁外贡献如实跟随，不等于整个顶点冻结。

## 唯一可恢复判定

业务只接受**唯一可恢复**的补偿，避免交付一条在当前父矩阵下看似无误、但含有拍脑袋填入的局部通道的编辑轨。对每一种挂接形态：

1. 先允许各键矩阵系数取任意有理数，以全时域世界矩阵相等为条件。这在每个切点区间上是一个精确线性系统：补偿轨逐键线性插值，要求 父世界(新) × 补偿 = 锁定世界(旧) 作为多项式恒等式成立（脱挂时父世界为单位矩阵）。
2. 无解或有多个解，该形态不可交付。**不得把逐键逆矩阵是否存在当成唯一性判据**：某个时刻父矩阵不可逆，不表示整条补偿轨不能唯一确定；父矩阵整段退化时补偿通常不唯一，不得用任意填零发布。
3. 恰有一解时，再判断全部键系数能否编码为旧十进制。全时域有解但无法编码（例如必须写入 1/3）也不可交付，且与代数无解区分开。

某个锁有至少一种获准且可交付的形态就必须成功解决；两种都成立时任选其一——本实现**优先保留挂接**（确定的选择规则）。只有所有锁都能解决时才交付完整源文件。

## 调用结果

- **编译成功**：退出 0，把交付源原子新建到 `--output`（写临时文件 + fsync + 硬链接生效），不覆盖已有文件或符号链接。交付件可直接交给 `rig-pose --source`。stdout 给 JSON：

  ```json
  {"status": "compiled",
   "locks": {"prop": "kept"},
   "options": {"prop": ["kept", "detached"]}}
  ```

  `locks` 按锁定关节 ID 报出交付形态（`kept` 或 `detached`）；`options` 列出该锁全部获准且可交付的形态（含未中选者），便于核对“两种形态均可成立”的情形。

- **有锁不能解决**（请求合法）：退出 0，不创建输出，也不交付其他锁的半成品。stdout 给 `blocked` 及每个未能解决的关节，逐一说明各获准形态失败原因：

  ```json
  {"status": "blocked",
   "blocked": {"prop": {"kept": "no_exact_solution"},
               "prop_b": {"kept": "not_encodable"}}}
  ```

  原因取值：`no_exact_solution`（全时域世界矩阵相等无精确解）、`not_unique`（补偿不唯一）、`not_encodable`（唯一解超出原数值编码）。只列出获准的形态（`allow_detach` 为 false 时没有 `detached` 项）。

- **请求错误、I/O 错误、目标已存在（含符号链接）**：退出 2，stderr 给可读诊断，不输出成功结果；任何分支都不能覆盖旧文件。编辑与补偿使交付源超出原版上限（如轨道总数）也按请求错误处理。

## 交付示例

`examples/worldlock.py` 离线演示完整交付链：根静止、挂点局部 x 平移 2，替换根轨推 x 平移 0→1 → 保留挂接编译成功，旧采样入口直接打开交付件，子帧 t=1/2 处锁下后代姿态与编辑前一致、混合顶点仍随根运动；新根轨再让 x 缩放 1→2 → 禁止脱挂时报 `no_exact_solution`，允许脱挂时交付脱挂子树。运行：

```sh
python3 examples/worldlock.py
```
